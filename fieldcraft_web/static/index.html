What Fieldcraft does

AI writes a lot of the code now. Fieldcraft is how you tell whether that work was any good — and how you set limits on what the agent is allowed to do while it works.

Measure

Know how well it went

Every run is scored against the task's real tests and its acceptance criteria — not on whether the agent said it was finished. You get how many attempts it took, what it cost, and whether it actually works.

Govern

Decide what it may touch

Set the rules on a ticket: files the agent may not edit, and things it may never add — secrets, dynamic code execution, network calls. Every change is checked against those rules, and anything that breaks them is undone and recorded.

How a piece of work moves

1 Write a ticketWhat needs doing. Attach a repo or a spec if you have one.
→
2 Set the rulesOptional. What's off-limits for this piece of work.
→
3 Run itThe agent works in short attempts. You approve, comment, or reject each one — or let it run itself.
→
4 See the resultScored, with the full history of what happened and why.

You stay in the loop by choice, not by obligation — and either way the result is measured the same.
