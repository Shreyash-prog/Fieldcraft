Platform & ops

Production provenance

“When this breaks in production, how did the AI build it?”

The problem

Every other lens stops at shipped. Ops lives with what shipped — at 3am, on a pager, with zero visibility into how the thing that broke was actually made. Which model, under which policy, steered by whom, at which attempt, with what reverted along the way. All of it gone by the time it matters.

What Fieldcraft does

Fieldcraft traces a production incident back to the run that produced the code, and then closes the loop the other way. Production is the one signal that cannot be argued with, so what it proves goes back into the standard: an incident becomes a gate check, and the next run cannot repeat it.

Key capabilities

  • Incident-to-provenance trace — from an alert to the exact run that wrote the code.
  • Faster root cause — the attempts, reverts and steering are already recorded.
  • Deploy-time risk — how this change was built, surfaced before it goes out.
  • Fragility mapping — which build patterns keep turning into incidents.
  • Incidents become gate checks — production truth hardens the standard permanently.

Production is the one measurement that can't be gamed. A judge can be optimised against and a review can be rubber-stamped. An outage is an outage — which makes it the strongest possible input to the gate.
